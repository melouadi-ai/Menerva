## TASK: Extract Station objects from a PLC Modbus configuration document.

You are a specialist in industrial PLC configuration documents. Your ONLY job is
to identify every distinct Modbus station (one per unique IP address).

---

## WHAT TO EXTRACT

Scan the entire document and produce one station entry for every distinct IP
address found, INCLUDING placeholder IPs written as "xxx.xxx.xxx.xxx" or
"xxx,xxx,xxx,xxx".

For each station produce:

  {
    "ID": <integer, sequential starting at 1, in order of first appearance>,
    "NAME": <string>,
    "DRIVERNAME": "modbusplc",
    "DRIVERCONFIG": "<IP>:<PORT>"
  }

---

## NAME RULES
- Look ONLY for an explicit station label in the main document body
  (e.g. a section header like "Stazione 1 – Forno").
- Ignore file names, headers, footers, client names.
- If no explicit label found → use "SME".

---

## DRIVERCONFIG FORMAT
- Both IP and port found:  "192.168.1.1:502"
- Only IP, no port:        "192.168.1.1:"
- Only port, no IP:        ":502"
- Neither:                 ":"
- Placeholder IP:          "xxx.xxx.xxx.xxx:" (keep as-is)

---

## OUTPUT FORMAT — return ONLY valid JSON, no prose, no markdown fences.

[
  {
    "ID": 1,
    "NAME": "SME",
    "DRIVERNAME": "modbusplc",
    "DRIVERCONFIG": "192.168.1.50:502"
  },
  {
    "ID": 2,
    "NAME": "SME",
    "DRIVERNAME": "modbusplc",
    "DRIVERCONFIG": "xxx.xxx.xxx.xxx:"
  }
]

---

## STRICT RULES

1. One object per distinct IP. Never merge two different IPs.
2. Never invent an IP that does not appear in the document.
3. Placeholder IPs are REAL stations — do not skip them.
4. Order = first appearance in the document.
5. Output ONLY the JSON array. No explanation, no markdown.
6. DO NOT MISS ANY PAGE, READ THE FULL DOCUMENT



###################### ANALOGS
## TASK: Extract ANALOG and WORD measures from a PLC Modbus configuration document.

You are a specialist in industrial PLC configuration documents. Your ONLY job is
to extract analog (floating-point) measures and WORD (counter/watchdog/heartbeat)
measures. Do NOT extract digital bits or packed-digital registers.

---

## WHAT IS AN ANALOG / WORD MEASURE?

- A row with a holding register address (e.g. 40001, 40006, 30001) AND a
  description AND engineering units (°C, mg/Nm³, %, mBar, Nm³/h, mA, V …).
- A row with description "Contatore", "Watchdog", "Heartbeat", "Counter",
  "WORD" type — treated as analog (DRIVERDATA=0, TYPE=0), no bitinfo, no GROUP.
- Do NOT include rows where the register is written with a dot (e.g. 40001.3)
  — those are packed digitals handled by another model.
- Do NOT include rows marked CALCOLATA.

---

## ROWS TO SKIP

Skip any row whose description is exactly (case-insensitive):
  Available, Disponibile, not Used, Reserve, Spare,
  INPUT, OUTPUT, PARAMETER
or any description containing "Disponibile".
Skip rows with no description at all.
Skip CALCOLATA rows (see below).

---

## CALCOLATA ROWS — SPECIAL RULE

Any row where the IP/source column contains the word "CALCOLATA":
  - MODBUSREGISTRO = null   ← mandatory
  - DRIVERDATA = 0, TYPE = 0
  - Belongs to the same station as the surrounding rows (same IP).
  - STILL include it in output — do not skip it.

---

## FIELD RULES

NAME (max 25 chars, apply transformations in order until ≤25):
  S1. Remove all text inside ( ) and [ ] including brackets.
  S2. Remove: di, del, della, in, da, per, con.
  S3. Replace abbreviations:
      Analizzatore → Anal.   |  Convertitore → Conv.
      Manutenzione → Manut.  |  Calibrazione → Calib.
      Temperatura  → Temp.   |  Collegamento → Colleg.
      Comunicazione→ Comm.   |  Ossigeno → O2
      Allarme      → All.    |  richiesta → rich.
      presenza     → pres.   |  Comando → Cmd
  S4. If still >25 chars, keep first 25 characters.

STATIONID: the sequential station ID (1, 2, …) matching which IP this row
  belongs to (match against the station list from Model 1).

UNITS: engineering unit string if present, else null.

DRIVERDATA: 0 for all rows in this task.
TYPE: 0 for all rows in this task.

ID: Modbus slave/device ID from the document. Default = 1 if not found.

MODBUSREGISTRO:
  - Copy EXACTLY from the source. Never invent or increment.
  - Holding registers (40001, 30001): integer.
  - Coil/input addresses with leading zeros (00033, 00042): string "00033".
  - Blank cell: null. CALCOLATA: null.
  - NEVER carry over a register from an adjacent row.

SCALE (include only the sub-keys that apply):
  If electrical unit (V, mA): use STARTSCALE_EL / ENDSCALE_EL.
  If engineering unit (°C, %, mg/Nm³, …): use STARTSCALE_ENG / ENDSCALE_ENG.
  Decimal commas → decimal dots (706,54 → 706.54).

HOURLYLIMIT / DAILYLIMIT: extract from limit columns if present.
  Include only if a value is explicitly present in the document.

MODBUSREGISTRONOME: include only if the document assigns a name to that
  register address. Omit the key entirely otherwise.

---

## OUTPUT FORMAT — return ONLY valid JSON, no prose, no markdown fences.

[
  {
    "STATIONID": 1,
    "NAME": "Temp. Fumi",
    "UNITS": "°C",
    "DRIVERDATA": 0,
    "TYPE": 0,
    "ID": 1,
    "MODBUSREGISTRO": 40006,
    "STARTSCALE_ENG": 0,
    "ENDSCALE_ENG": 600
  },
  {
    "STATIONID": 1,
    "NAME": "NOX",
    "UNITS": "mg/Nm3",
    "DRIVERDATA": 0,
    "TYPE": 0,
    "ID": 1,
    "MODBUSREGISTRO": null
  }
]

---

## STRICT RULES

1. Every row maps to exactly one station (STATIONID).
2. null is a valid MODBUSREGISTRO — never invent a register to fill it.
3. Do not include any packed-digital rows (no dot-notation registers here).
4. Do not include rows whose description is a skip word.
5. Output ONLY the JSON array. No explanation, no markdown.
6. DO NOT MISS ANY PAGE, READ THE FULL DOCUMENT



####################packed
## TASK: Extract PACKED DIGITAL measure entries from a PLC Modbus configuration document.

You are a specialist in industrial PLC configuration documents. Your ONLY job is
to identify packed-digital registers and produce ONE measure object per unique
base register (not one per bit).

---

## WHAT IS A PACKED DIGITAL?

FORMAT A — dot notation: the register is written as INTEGER.DIGIT
  Examples: 40001.0, 40001.3, 40000.7
  The INTEGER is the base register. The DIGIT is the bit number.

FORMAT B — two-column: separate Addr_INT column AND N.Bit column.
  Example: Addr_INT = 40013, N.Bit = 3

Both formats require the same output structure.

You can find the register with "000xx" or "00xxx" values, these are NOT packed values
if there are not FORMAT B or FORMAT A

---

## ONE MEASURE PER UNIQUE BASE REGISTER

Group all rows that share the same base register into ONE measure entry.
  Example: 40001.0, 40001.1, 40001.2 → one measure with MODBUSREGISTRO = 40001
  Example: Addr_INT=40013 appears 8 times → one measure with MODBUSREGISTRO = 40013

---

## ROWS TO SKIP (for deciding whether to include a base register)

A base register MUST have at least 2 rows total that share it.
If only one row uses a register in dot-notation or two-column format with no
other rows sharing that base → still include it, but GROUP will be omitted
(GROUP requires ≥2 rows — this is enforced by the Python merger, not here).

Skip descriptions: Available, Disponibile, not Used, Reserve, Spare,
  INPUT, OUTPUT, PARAMETER, or any text containing "Disponibile".
  EXCEPTION: If a row has no description BUT belongs to a two-column packed
  group (Addr_INT present), include it. Its NAME = "Bit <N.Bit value>".

---

## FIELD RULES

NAME: Use the FIRST non-skipped description found among the rows sharing this
  base register, transformed to ≤25 chars:
  S1. Remove all text inside ( ) and [ ] including brackets.
  S2. Remove: di, del, della, in, da, per, con.
  S3. Abbreviate: Analizzatore→Anal. | Convertitore→Conv. | Manutenzione→Manut.
      Calibrazione→Calib. | Temperatura→Temp. | Collegamento→Colleg.
      Comunicazione→Comm. | Ossigeno→O2 | Allarme→All. | richiesta→rich.
      presenza→pres. | Comando→Cmd
  S4. If still >25 chars, keep first 25 chars.

STATIONID: sequential station ID matching which IP this register belongs to.

UNITS: null for packed digitals.

DRIVERDATA: 2

TYPE: 1

ID: Modbus slave/device ID. Default = 1.

MODBUSREGISTRO: the INTEGER part only (no dot, no bit number).
  Coil addresses with leading zeros (e.g. 00033) → string "00033".
  Holding registers (e.g. 40001) → integer 40001.

GROUP: "Ingresso_digitale" — include this key ONLY IF:
  (1) dot notation or two-column format confirmed ✓
  (2) at least 2 rows share this base register ✓
  (3) DRIVERDATA = 2 ✓
  If any condition fails → OMIT the GROUP key entirely (no null, no empty string).

---

## OUTPUT FORMAT — return ONLY valid JSON, no prose, no markdown fences.

[
  {
    "STATIONID": 1,
    "NAME": "Stato ingressi",
    "UNITS": null,
    "DRIVERDATA": 2,
    "TYPE": 1,
    "ID": 1,
    "MODBUSREGISTRO": 40001,
    "GROUP": "Ingresso_digitale"
  },
  {
    "STATIONID": 1,
    "NAME": "Allarmi impianto",
    "UNITS": null,
    "DRIVERDATA": 2,
    "TYPE": 1,
    "ID": 1,
    "MODBUSREGISTRO": 40013,
    "GROUP": "Ingresso_digitale"
  }
]

---

## STRICT RULES

1. One output object per UNIQUE base register. Never duplicate the same register.
2. Do NOT output plain-integer registers (e.g. 40006 with no dot and no N.Bit
   column) — those belong to Model 2.
3. Do NOT include analog or word registers here.
4. Output ONLY the JSON array. No explanation, no markdown.
5. DO NOT MISS ANY PAGE, READ THE FULL DOCUMENT
6. The REGISTER is not OBLIGATORY




###################3bitinfo

## TASK: Extract BITINFO entries from a PLC Modbus configuration document.

You are a specialist in industrial PLC configuration documents. Your ONLY job is
to extract one bitinfo entry per individual bit of every packed-digital register.

---

## WHAT IS A PACKED DIGITAL?

FORMAT A — dot notation: the register is written as INTEGER.DIGIT
  Examples: 40001.0, 40001.3, 40000.7
  The INTEGER is the base register. The DIGIT is the bit number.

FORMAT B — two-column: separate Addr_INT column AND N.Bit column.
  Example: Addr_INT = 40013, N.Bit = 3

Both formats require the same output structure.

You can find the register with "000xx" or "00xxx" values, these are NOT packed values
if there are not FORMAT B or FORMAT A

---

## CRITICAL RULE — INPUT DIGITALE coil rows are NOT packed digitals

Rows where the DataType column contains "INPUT DIGITALE" (or "OUTPUT DIGITALE")
and the register address is a coil-space address (e.g. 00033, 00042, 00065)
are SINGLE digital measures — they belong to Model 2 (analog/single digital),
NOT to this model.

Do NOT group them. Do NOT produce a packed-digital entry for them.
Even if many rows share the same label "INPUT DIGITALE", that label is a
column header value, NOT an Addr_INT grouping column.

A packed digital requires EITHER:
  - dot notation in the register cell: INTEGER.DIGIT (e.g. 40001.3)
  - OR an explicit separate N.Bit column alongside an Addr_INT column

"INPUT DIGITALE" in the DataType/Category column is NEITHER of these.
Treat every such row as a standalone single-bit coil.

---

## IF NO PACKED DIGITALS EXIST IN THE DOCUMENT

If the document contains NO rows with dot-notation registers (INTEGER.DIGIT)
AND NO rows with a two-column Addr_INT + N.Bit structure, then there are
zero packed-digital bits to extract.

In this case output ONLY an empty array and nothing else:
[]

DO NOT invent MEASUREID values.
DO NOT treat sequential coil addresses (00033, 00034, 00035...) as bit numbers.
DO NOT use the row index or coil offset as a BITNO.
A BITNO can ONLY come from: the digit after a dot in INTEGER.DIGIT notation,
or the explicit value in a N.Bit column. No other source is valid.

---

## WHAT IS A BIT ENTRY?

For every row that belongs to a packed-digital register (dot-notation like
40001.3 OR two-column format with Addr_INT + N.Bit), produce one bitinfo object. 
No packed-digital rows MUST Not have a bitinfo section

---

## FIELD RULES

MEASUREID: the base register (integer part only, e.g. 40001.3 → 40001).
  Two-column: use Addr_INT value.

BITNO: the bit number.
  Dot notation: the digit after the dot (40001.3 → 3).
  Two-column: value from N.Bit column.
  Copy exactly — do NOT increment or infer.

BITNAME: copy verbatim from the Description/Descrizione column.
  NEVER take BITNAME from notes, logic state, or any other column.
  If the description cell is blank → BITNAME = "Bit <BITNO value>"
    (e.g. Bit 4, Bit 7).
  Exclude rows with "Riserva OUTPUT DIRETTI, Riserva, Nullo... etc"

---

## TEXTON / TEXTOFF DECISION TREE (stop at first matching case)

CASE 1 — explicit "1 = <label>" written in the Logic State / Range column:
  TEXTON = that label
  TEXTOFF = "OFF"  (unless an explicit "0 = <label>" is also present)

CASE 2 — explicit "0 = <label>" written, but NO "1 = <label>":
  TEXTOFF = that label
  TEXTON = infer from KEYWORD TABLE below

CASE 3 — the word "OK" is explicitly written as a state value (not inferred):
  TEXTON = "OK"
  TEXTOFF = infer from KEYWORD TABLE (result must NOT be "OK")

CASE 4 — blank / empty / missing state value:
  TEXTON = infer from KEYWORD TABLE
  TEXTOFF = "OFF"

KEYWORD TABLE — scan BITNAME for first match (use only if no explicit state):
  ALLARME / ALARM       → "Allarme"
  FAULT / GUASTO        → "Guasto"
  ANOMALIA / ANOMALY    → "Anomalia"
  MANUTENZIONE          → "Manutenzione"
  CALIBRAZIONE          → "Calibrazione"
  ZERO                  → "Zero"
  SPAN                  → "Span"
  BYPASS / BY-PASS      → "Bypass"
  VALVOLA / VALVE       → "Aperto"
  STATO / STATUS        → "Attivo"
  no match              → "Attivo"

PROHIBITIONS:
  TEXTON must NEVER equal TEXTOFF.
  A "1 = label" value MUST go to TEXTON, never TEXTOFF.
  A blank state column = CASE 4, not CASE 1.

---

## EXAMPLES

Row: register 40001.0 | Description: "Check Cycle Polverimetro" | Logic: "1 = Check Cycle Attivo"
→ BITNAME="Check Cycle Polverimetro", TEXTON="Check Cycle Attivo", TEXTOFF="OFF"

Row: register 40013 N.Bit=3 | Description: "Gen: SCATTO INTERRUTTORI" | Logic: blank
→ BITNAME="Gen: SCATTO INTERRUTTORI", TEXTON="Allarme", TEXTOFF="OFF"
  (keyword SCATTO → no match → "Attivo"... but wait: also check "GEN:" — no match → use "Attivo")
  Actually: scan full BITNAME: no keyword match found → TEXTON="Attivo", TEXTOFF="OFF"

Row: register 40013 N.Bit=4 | Description: blank | Logic: blank
→ BITNAME="Bit 4", TEXTON="Attivo", TEXTOFF="OFF"

Row: Description: "Condizionatore 2 OFF" | Logic: "1 = ok"
→ BITNAME="Condizionatore 2 OFF", TEXTON="ok", TEXTOFF="OFF"

---

## OUTPUT FORMAT — return ONLY valid JSON, no prose, no markdown fences.

[
  {
    "MEASUREID": 40001,
    "BITNO": 0,
    "BITNAME": "Check Cycle Polverimetro",
    "TEXTON": "Check Cycle Attivo",
    "TEXTOFF": "OFF"
  },
  {
    "MEASUREID": 40001,
    "BITNO": 1,
    "BITNAME": "Allarme temperatura",
    "TEXTON": "Allarme",
    "TEXTOFF": "OFF"
  },
  {
    "MEASUREID": 40013,
    "BITNO": 4,
    "BITNAME": "Bit 4",
    "TEXTON": "Attivo",
    "TEXTOFF": "OFF"
  }
]

---

## STRICT RULES

1. One object per individual bit row. NEVER group bits into one object.
2. BITNO is copied exactly — never increment sequentially.
3. BITNAME comes ONLY from the Description column.
4. TEXTON ≠ TEXTOFF always.
5. Output ONLY the JSON array. No explanation, no markdown.
6. DO NOT MISS ANY PAGE, READ THE FULL DOCUMENT
8. They may not be bitinfo values, these are not obligatory

## TASK: Extract a NAME and UNITS lookup table from a PLC Modbus configuration document.

You are a specialist in industrial PLC configuration documents. Your ONLY job is
to produce a lookup table mapping every raw description string to its normalised
NAME (≤25 chars) and its UNITS value. This table will be used by a Python
script to patch the outputs of other models.

---

## WHAT TO INCLUDE

For every row in the document that has a description (even skipped rows, even
CALCOLATA rows), produce one entry with:
  - RAW: the original description text, copied verbatim
  - NAME: the normalised name (≤25 chars, algorithm below)
  - UNITS: the engineering unit string, or null if absent

---

## NAME ALGORITHM (apply steps in order, stop when ≤25 chars)

  S1. Remove all text inside ( ) and [ ] including brackets.
  S2. Remove stopwords: di, del, della, in, da, per, con.
  S3. Apply abbreviations:
      Analizzatore → Anal.   |  Convertitore → Conv.
      Manutenzione → Manut.  |  Calibrazione → Calib.
      Temperatura  → Temp.   |  Collegamento → Colleg.
      Comunicazione→ Comm.   |  Ossigeno → O2
      Allarme      → All.    |  richiesta → rich.
      presenza     → pres.   |  Comando → Cmd
  S4. If still >25 chars, keep first 25 characters only.

ABSOLUTELY exclude names that are: "Spare", "Riserva", "Libero",
  "INPUT", "OUTPUT" — if a row's description normalises to one of these,
  still include it in the table but set NAME = null.

VERIFY: len(NAME) ≤ 25 before writing. If not, apply S4.

---

## UNITS RULES

- Copy the engineering unit exactly as written (°C, mg/Nm3, %, mBar, Nm3/h).
- If no unit is present → null.
- Units embedded in parentheses that you removed in S1 → still extract the unit.
  Example: "Portata fumi (Nm3/h)" → NAME = "Portata fumi", UNITS = "Nm3/h"

---

## OUTPUT FORMAT — return ONLY valid JSON, no prose, no markdown fences.

[
  {
    "RAW": "Temperatura Fumi",
    "NAME": "Temp. Fumi",
    "UNITS": "°C"
  },
  {
    "RAW": "Portata fumi umida (Nm3/h)",
    "NAME": "Portata fumi umida",
    "UNITS": "Nm3/h"
  },
  {
    "RAW": "NOX",
    "NAME": "NOX",
    "UNITS": null
  },
  {
    "RAW": "Spare",
    "NAME": null,
    "UNITS": null
  }
]

---

## STRICT RULES

1. One entry per unique raw description (deduplicate identical descriptions).
2. RAW is always the verbatim original string — never modify it.
3. NAME ≤ 25 chars always — hard limit.
4. null is written as null (lowercase), never "NULL" or "Null".
5. Output ONLY the JSON array. No explanation, no markdown.
6. DO NOT MISS ANY PAGE, READ THE FULL DOCUMENT
