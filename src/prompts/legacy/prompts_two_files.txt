### DOCUMENT TYPE: STATION INFORMATION

The document is divided into sections; extract information **only** from the following:

- **SUPERVISOR Section:** Identify and extract exclusively the communication protocol type for the station under analysis.
- **IP ADDRESSES Section:** Identify the IP address and port of the PLC. Pay close attention to extracting only the IP belonging to the PLC (excluding any other IP addresses in the section) and the port uniquely associated with that address.
  If multiple devices are listed (e.g. Gateway, HMI, PLC), filter the data and return only those explicitly labelled as PLC.
- **SCALE FIELDS Section:** For each element, extract the related tag, field, daily limit, and hourly limit.
  Make sure each limit (scale start and end — daily/hourly) is correctly associated with its reference tag.

#### Station level

- **nome_stazione:** Name of the reference station or identifier of the measurement point or plant (e.g. Furnace 1, SO2 processing plant).

  **CRITICAL EXCLUSIONS — READ CAREFULLY:**
  - STRICTLY IGNORE any text found in document headers, footers, margins, or page borders (e.g. "IKW", "Rev.", dates, company acronyms, revision codes). These are document metadata, NOT station names.
  - STRICTLY IGNORE the file name or document title. The file name is NEVER the station name.
  - DO NOT use individual tag descriptions, variable names, or zone names found inside table fields.
  - DO NOT use client names, project codes, or any text appearing before the main data table.

  **VALID SOURCE:** The station name must come ONLY from an explicit label in the main body of the document that clearly identifies the measurement station or plant (e.g. a section header like "Station 1 – Furnace", a dedicated "Station" column, or a clearly labelled station block).

  **DEFAULT BEHAVIOUR:** If no explicit station name is found in the main body, you MUST output the default value **"SME"** — no exceptions, no guessing, no use of acronyms from headers or file names. (EMISSION ANALYSIS SYSTEM → SAE, EMISSION MONITORING SYSTEM → SME)

- **stazione:** The textual identifier of the measurement point or plant.
- **protocollo:** The communication method. If you find words like  , MODBUS TCP, MODBUS TCP/IP the protocol is always **ModBus TCP**.
- **ip_plc:** The unique network address of the controller (format: xxx.xxx.xxx.xxx). Take ONLY the PLC IP, not other IP addresses.
- **port:** The TCP port number as an integer (e.g. 502, 5021). If absent, insert null.

#### Variable level

- **tag_variabile:** Tag of the measurement variable (e.g. SO2, O2U, P_TOT_TRB).
- **unità_misura:** The associated engineering unit (e.g. °C, bar, Nm3/h). This data is very important — pay attention when inserting it.
- **inizio_scala_elettrico:** The lower limit of the input signal range (e.g. 4 if the signal is 4–20 mA, or 0 if 0–10 V). Exists **only** if the unit of measure is V or mA.
- **fine_scala_elettrico:** The upper limit of the input signal range. Exists **only** if the unit of measure is V or mA.
- **inizio_scala_ingegneristico:** The real minimum value corresponding to the lower limit of the signal. Exists **only** if the unit of measure is mg/Nm3, %, mBar, °C, or other non-electrical units.
- **fine_scala_ingegneristico:** The real maximum value corresponding to the upper limit of the signal. Exists **only** if the unit of measure is mg/Nm3, %, mBar, °C, or other non-electrical units.
- **limite_orario:** Maximum numerical threshold calculated on the hourly average of samples. Usually found under the columns "Hourly Limit / Daily Limit / Hourly avg. limit value". This field is very important — do not skip it.
- **limite_giornaliero:** Numerical alarm threshold not to be exceeded in the respective time interval. This field is very important — do not skip it.

> Only **one pair** can exist: either (start/end electrical scale) OR (start/end engineering scale). The presence of one excludes the other; the unit of measure tells you which type applies.

#### General extraction rules

**DESCRIPTION:**

- You must also skip descriptions that **contain** the word "Available" or "Disponibile" within them (e.g. "OVF Misura Disponibile" must be discarded because it contains "Disponibile").
- This exclusion rule applies to both normal measure records and the BITINFO section.
- If the description cell is empty, skip the creation of that record.

- ANALYSE EVERY ROW — do not skip even a single row with a valid description.

**MEASUREMENT POINT NAME (field `nome`):**
- ABSOLUTELY exclude rows with names like "Spare", "Riserva", "Libero", "INPUT", "OUTPUT", or with an empty cell.
- Names longer than 25 characters MUST be shortened intelligently while keeping the same meaning. Remove content in brackets. The 25-character limit is a target, NOT a hard cutoff — never truncate a word mid-character to fit the limit. If the shortest meaningful version slightly exceeds 25 characters, accept it as-is. **MODBUS REGISTER (`modbus_registro`):**

- **CRITICAL - IGNORE "INDIRIZZO" COMPLETELY:** You must completely ignore the first column (`INDIRIZZO`). Values like `DBX 64.0`, `DBX 65.1`, etc., are strictly prohibited. DO NOT extract `64`, `65`, or `66` as registers under any circumstances.
- **LOCATE "REG" COLUMN:** The Modbus register base value is found in the column named **`REG`**. In this document, these are small integers (e.g., `1`, `2`).
- **HANDLE MERGED CELLS BY INHERITANCE (CRITICAL):** Because the `REG` column uses vertically merged cells, only the first row of a block contains a number. For all subsequent rows where the `REG` space is blank, **you MUST explicitly copy the last seen value from the rows above**.
  - *Example 1:* For tag `AL_SONDA`, the REG column shows `1`. The calculated register is `40001`.
  - *Example 2:* For tag `AL_LINEA` directly below it, the REG column is visually blank. You MUST inherit the `1` from above. The calculated register is `40001`.
  - *Example 3:* For tag `AL_BOX`, the REG column shows `2`. The calculated register is `40002`.
- **APPLY OFFSET (4xxxx):** Add the extracted or inherited `REG` value to 40000 to form the final `modbus_registro` (e.g., REG `1` -> `40001`, REG `2` -> `40002`).
- **BIT IS SEPARATE:** The number in the column exactly next to REG (the `BIT` column, e.g., 8, 9, 10) is the `bit_posizione`. It is NEVER the `modbus_registro`.
- **SPECIAL WORD TYPES:** If the data type (`TIPO`) is "WORD" and the description represents a **counter** (e.g., "Counter 0–999"), a **watchdog**, or a **heartbeat**:
  - The `modbus_registro` must be exactly **0**.
  - It must be treated as an analog/integer measurement.
  - There must be NO records in BITINFO (but it MUST be present in measures).

**SIGNAL TYPE:**
- **analogico = 1** if the value is a continuous measurement (REAL, INT, UINT, numeric WORD without bits) e.g. temperature, level, pressure; otherwise 0.
- **digit_singolo = 1** if the measurement point has a BOOL signal (on/off), or a WORD without a unit of measure (or with unit 0/1), AND the register is NOT shared with other measurement points; otherwise 0.
  - If the same register number is used by more than one measurement point → it is NOT single digital but **packed**.
- **digit_impaccato = 1** if the signal is of type WORD with bit references, or if multiple measurement points use the same register with different bits → ALL those variables are packed digital type.
  - If you find the notation `40001.x` (register + dot + bit number) → **always** packed digital.
  - If you find multiple entries with the same register but in a column where bits are indicated (from 0 to 15 or from 1 to 16) → **always** packed digital.

**BIT POSITION (`bit_posizione`):**
- The bit position (0–15) within the register.
- BITNO values are not necessarily incremental; they can vary freely, e.g. 40000.0, 40000.15, 40001.3, 40001.6, 40001.9, 40001.12 → the BITNOs will be: 0, 15, 3, 6, 9, 12.
- For analog measurements or those occupying the entire register, the value is **null**.
- DO NOT insert the bit value inside `modbus_registro`. They are two distinct fields.
