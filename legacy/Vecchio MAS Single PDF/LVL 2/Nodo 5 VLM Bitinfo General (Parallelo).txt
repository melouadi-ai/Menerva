- Return ONLY the JSON defined in <output_schema>.

---

## WHAT TO EXTRACT

Produce one `bitinfo` entry for every row that meets ONE of these two conditions:

**Condition 1 — Packed digital**
- The register is in dot notation: `INTEGER.DIGIT` (e.g. `40001.0`, `40007.3`).
- NOTE: `40000.0` IS dot notation — `.0` means bit 0, not a decimal.
- At least 2 rows in the document share the same base register.

**Condition 2 — Single digital (standalone)**
- The row is a digital signal: BOOL, WORD with no unit or unit = 1/0, TYPE = 6, column label "INPUT DIGITAL" or "OUTPUT DIGITAL".
- The register is a plain integer with NO dot notation.
- The register is NOT shared with any other row in the same station.
- These rows are NOT included in `measures`, so they go here.

Produce ONE entry per qualifying row — not one per register.

---

## WHEN THERE ARE NO QUALIFYING ROWS

If the document contains no rows meeting either condition above:

<example>
[
  {
    "NAME": "SME",
    "DRIVERNAME": "modbusplc",
    "DRIVERCONFIG": ":",
    "ID": 1,
    "measures": [],
    "bitinfo": []
  }
]
</example>

`bitinfo` MUST be `[]`. Do not invent entries. Return this structure immediately.

---

## FIELDS

For every packed digital row, extract:
- Base register and bit number (see PACKED DIGITAL FORMATS below)
- BITNAME from the Description column, it is the name of the measure
IMPORTANT: BITANME AND STATE_VALUE (LOGIC STATE / RANGE COLUM) ARE TOTALLY DIFFERENT CASES

### Packed digital

MEASUREID |  Integer part of the register: 40001.3 → 40001 |
BITNO | Digit after the dot: 40001.3 → 3. Copy exactly — never increment sequentially. |
BITNAME | Copy VERBATIM from the Description column only. Never from Notes, State, or Range. Never leave empty. |


<example>
40001.0 → MEASUREID: 40001, BITNO: 0
40007.3 → MEASUREID: 40007, BITNO: 3
40001.8 → MEASUREID: 40001, BITNO: 8
</example>

### Single digital (standalone)

MEASUREID | Register as-is. Preserve leading zeros as a string. |
BITNO | Always 0 — standalone digitals have no bit subdivision. |
BITNAME | Copy VERBATIM from the Description column only. | DO NOT MISS THIS FIELD

<example>
00033 → MEASUREID: "00033", BITNO: 0
40010 → MEASUREID: 40010,  BITNO: 0
</example>

## STATION RULES

NAME: Look for labels like "Punto emissivo", "Camino", "Emissione", "SAE". If absent -> "SME". Always write the full name found in the text.
DRIVERNAME | If Modbus protocol → "modbusplc" |
DRIVERCONFIG | Format "IP:PORT". See table below. |
ID | Sequential integer starting at 1, in document order. |

**DRIVERCONFIG rules:**

Both IP and port found | "192.168.1.1:502" |
IP only | "192.168.1.1:"
Port only | ":502"
Neither | ":"
Placeholder IP (`xxx.xxx.xxx.xxx` or `xxx,xxx,xxx,xxx`) | Does NOT form a separate station. Inherits the DRIVERCONFIG of the main station. |

DO NOT invent IP or port. The IP may appear anywhere on the page.

---

## GENERAL RULES

- Order: follow document row order, top to bottom. Never reorder.
- null values: write `null` (lowercase).
- One station object per distinct station in the source.
- A plain integer register shared by multiple analog rows is NOT a packed digital and MUST NOT appear in `bitinfo`.
